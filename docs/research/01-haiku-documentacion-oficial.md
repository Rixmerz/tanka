# Claude Haiku 4.5 como asistente personal/secretario con MCP: hechos documentados e inferencias

Fecha de investigación: 2026-09-16. **No existe ningún Haiku más nuevo que 4.5.** La tabla oficial de modelos actuales lista Fable 5.1, Opus 5, Sonnet 5 y Haiku 4.5; Haiku sigue en la generación 4.5 con retiro "no antes del 15-oct-2026" (https://platform.claude.com/docs/en/about-claude/models/overview). Búsquedas de "Haiku 5" solo devuelven rumores no confirmados por Anthropic.

Convención: **[HD]** = hecho documentado en fuente oficial; **[INF]** = inferencia a partir de esos hechos.

---

## 1. Ficha técnica y features soportadas (API)

Fuentes: https://platform.claude.com/docs/en/models/haiku-4-5/overview y https://platform.claude.com/docs/en/about-claude/models/overview

- [HD] ID `claude-haiku-4-5-20251001` (alias `claude-haiku-4-5`). Lanzado 15-oct-2025. Descripción oficial: "The fastest model with near-frontier intelligence". Latencia comparativa: "Fastest".
- [HD] Context window **200K** (vs 1M en Sonnet 5/Opus 5/Fable 5.1). Max output **64K** (vs 128K). Sin soporte de 300K output en Batch (solo modelos 4.6+).
- [HD] Precio **$1 / $5 por MTok** (input/output). Cache: 5m write $1.25, 1h write $2, read $0.10. Batch 50% dto.
- [HD] Knowledge cutoff fiable **feb-2025**, datos hasta jul-2025 (Sonnet 5: ene-2026; Opus 5: may-2026).
- [HD] **Thinking: solo "Extended" manual** (`thinking: {type:"enabled", budget_tokens:N}`); `type:"adaptive"` devuelve 400. `budget_tokens` mínimo 1.024 y menor que `max_tokens`. **Effort: "Not supported"** (https://platform.claude.com/docs/en/build-with-claude/thinking-troubleshooting, https://platform.claude.com/docs/en/build-with-claude/extended-thinking).
- [HD] **No soporta interleaved thinking** (pensar entre tool calls): "Claude Haiku 4.5 does not support interleaved thinking. On the Claude API, the beta header is accepted but ignored." Además, con thinking manual `tool_choice: any/tool` no está soportado (solo `auto`/`none`) (https://platform.claude.com/docs/en/agents-and-tools/tool-use/define-tools). Haiku 4.5 descarta los thinking blocks de turnos previos.
- [HD] Vision, tool use, prompt caching (mínimo cacheable **4.096 tokens**, más alto que otros modelos), structured outputs y strict tool use (soportado, sin beta header), **tool search / `defer_loading`**: soportado (`tool_search_tool_regex_20251119`, `tool_search_tool_bm25_20251119`) (https://platform.claude.com/docs/en/build-with-claude/prompt-caching, https://platform.claude.com/docs/en/build-with-claude/structured-outputs, https://platform.claude.com/docs/en/agents-and-tools/tool-use/tool-search-tool).
- [HD] **Compaction server-side: NO soportado** (https://platform.claude.com/docs/en/build-with-claude/compaction). Tampoco fast mode, task budgets ni mid-conversation system messages.
- [HD] MCP connector (beta `mcp-client-2025-11-20`): la doc no lista restricciones por modelo; solo tool calls (no resources/prompts), solo servidores HTTP/SSE remotos, no elegible ZDR (https://platform.claude.com/docs/en/agents-and-tools/mcp-connector).
- [HD] Migración: solo `temperature` O `top_p` (ambos → 400); manejar `stop_reason: refusal`; "Claude 4 models have a more concise, direct communication style" (https://platform.claude.com/docs/en/models/haiku-4-5/migration-guide).
- [HD] Context awareness: entrenado para saber cuánto contexto le queda y "wrap up" al acercarse al límite; útil para limitar "agentic laziness" (system card §1.1.3 https://www.anthropic.com/claude-haiku-4-5-system-card; https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices).
- [INF] Para un secretario que gestiona hilos largos de correo/chat, la combinación 200K + sin compaction + mínimo de caché 4K tokens obliga a gestionar el contexto en el cliente (resúmenes propios, `context_management` clear_tool_uses, o rotación de sesiones).

## 2. Benchmarks y posicionamiento oficial

- [HD] Anuncio (https://www.anthropic.com/news/claude-haiku-4-5): SWE-bench Verified **73.3%**; Terminal-Bench 40.21% (41.75% con 32K thinking); OSWorld 50.7%; "similar levels of coding performance" a Sonnet 4 a 1/3 del coste y >2× velocidad; "90% of Sonnet 4.5's performance" en la eval de Augment. Patrón recomendado literal: "Sonnet 4.5 can break down a complex problem into multi-step plans, then orchestrate a team of multiple Haiku 4.5s to complete subtasks in parallel."
- [HD] System card: "It is not a frontier model, but its high levels of intelligence and speed make it appropriate for a wide variety of 'agentic' uses, including where multiple instances of the model complete tasks in parallel." SWE-bench Verified hard subset: 36.6%. ASL-2.
- [HD] Guía de coste/inteligencia (https://platform.claude.com/docs/en/about-claude/models/optimizing-for-cost-and-intelligence): "Claude Haiku 4.5 answered GPQA Diamond questions at about a tenth of Opus 5's cost per question, with 63% accuracy compared with 92% for Opus, and fell much further behind on long coding tasks. **It fits high-volume work with checkable outputs, not long agentic loops.**" Los patrones orquestador/worker medidos usan Sonnet 5 como worker, no Haiku.
- [HD] Choosing a model (https://platform.claude.com/docs/en/about-claude/models/choosing-a-model): Haiku para "Real-time applications, high-volume intelligent processing, cost-sensitive deployments needing strong reasoning, sub-agent tasks"; enfoque "efficiency-first: empezar con Haiku, evaluar, subir solo si hay gaps". "Most workloads start with Claude Opus 5."
- [HD] Building effective agents (https://www.anthropic.com/engineering/building-effective-agents): routing de preguntas "easy/common" a Haiku y "hard/unusual" a Sonnet; los agentes conllevan "higher costs, and the potential for compounding errors".
- [INF] Anthropic nunca recomienda Haiku como *driver* de un loop agéntico largo; lo posiciona como worker/clasificador/respuesta rápida. Un secretario que solo triagea, redacta y llama 1-3 tools por turno encaja en "checkable outputs"; uno que planifica y encadena muchas acciones autónomas, no.

## 3. Debilidades documentadas relevantes para tool use

- [HD] Parámetros faltantes: "Claude Opus is much more likely to recognize that a parameter is missing and ask for it. Claude Sonnet might ask... But it might also infer a reasonable value... This behavior is not guaranteed, especially for more ambiguous prompts and **for less capable models**." (https://platform.claude.com/docs/en/agents-and-tools/tool-use/overview). [INF] Riesgo directo para enviar correos/mensajes: Haiku puede inventar destinatario, asunto o fecha en vez de preguntar → usar `strict: true`, enums, campos `required` y confirmación humana antes de tools con efectos irreversibles.
- [HD] System card §4.3: en checkpoints intermedios de entrenamiento se observaron "excessive tool calling, overengineering, and hallucinations"; §1.1.3 menciona "agentic laziness" como problema mitigado con context awareness. [INF] La doc no cuantifica loops en el modelo final; conviene poner límite de iteraciones y deduplicación de tool calls en el cliente.
- [HD] Prompt injection (system card §3.2, tablas 3.2.2.A-C): prevención sin safeguards en MCP **92.5%** (Sonnet 4.5: 92.0%), tool use **93.4%** (Sonnet 4.5: 96.0%), computer use 72.2% sin / 92.4% con clasificador. La eval MCP simulaba "email, Slack, and document collaboration servers" con instrucciones adversarias en mensajes/documentos. [INF] Un secretario que lee correos entrantes está exactamente en ese vector; ~7% de ataques exitosos sin safeguards es alto si el modelo puede enviar correos, por lo que los tools de escritura deben requerir confirmación.
- [HD] Evaluación awareness: 9% de transcripts con evaluación verbalizada (system card §4.1.1); menos emotivo por reducción de sycophancy (§4.6).
- [HD] Buenas prácticas de tools (https://platform.claude.com/docs/en/agents-and-tools/tool-use/define-tools): descripciones "extremely detailed... at least 3–4 sentences"; consolidar operaciones en menos tools con parámetro `action`; namespacing por servicio; respuestas de tool con solo información de alta señal; `input_examples` mejoró "accuracy from 72% to 90% on complex parameter handling" (https://www.anthropic.com/engineering/advanced-tool-use). Effective context engineering: "If a human engineer can't definitively say which tool should be used in a given situation, an AI agent can't be expected to do better"; usar "minimal viable set of tools" (https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents).
- [HD] Steering: con `tool_choice: auto` Claude decide por turno; frases como "Use the tools to investigate before responding" o "Use your judgment about whether to call a tool" ajustan la tendencia. El prompt de sistema de tool use añade 496 tokens en Haiku 4.5.
- [INF] Ninguna página oficial dice literalmente "drift de instrucciones en contexto largo" para Haiku; lo más cercano es el principio general de "context rot" ("the model's ability to accurately recall information from that context decreases" al crecer el contexto).

## 4. Claude Code y Haiku

- [HD] Alias `haiku`: "Uses the fast and efficient Haiku model for simple tasks". `ANTHROPIC_DEFAULT_HAIKU_MODEL`: "The model to use for `haiku`, or background functionality". Modelo por defecto de sesiones: Opus 5 o Sonnet 5 según plan; Haiku nunca es default principal. "Haiku models are always available and can't be disabled" (fallback garantizado). Una sesión Haiku sube a Sonnet en plan mode salvo que Sonnet esté excluido (https://code.claude.com/docs/en/model-config).
- [HD] Costes: "For simple subagent tasks, specify `model: haiku`"; para agent teams "Use Sonnet for teammates" (https://code.claude.com/docs/en/costs). Subagentes: `model: haiku|sonnet|opus|inherit`, `CLAUDE_CODE_SUBAGENT_MODEL` + `CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1`; ejemplos oficiales de Haiku: exploración/lectura con `tools: Read, Grep, Glob` (https://code.claude.com/docs/en/sub-agents).
- [INF] No hay frase oficial "Haiku no recomendado como modelo principal", pero todo el diseño (defaults, alias "simple tasks", upgrade automático en plan mode) lo trata como modelo de tareas ligeras/subagente.

## 5. MCP, número de tools y context bloat

- [HD] Tool search tool (https://platform.claude.com/docs/en/agents-and-tools/tool-use/tool-search-tool): un setup multiserver típico (GitHub, Slack, Sentry, Grafana, Splunk) consume "~55k tokens in definitions"; "Claude's ability to pick the right tool degrades once you exceed 30–50 available tools"; usar tool search con ≥10 tools o >10K tokens de definiciones; mantener 3-5 tools frecuentes sin deferir. Advanced tool use: "Opus 4 improved from 49% to 74%, and Opus 4.5 improved from 79.5% to 88.1%" en evals MCP con tool search; se han visto "tool definitions consume 134K tokens" (https://www.anthropic.com/engineering/advanced-tool-use). No hay cifras específicas de Haiku.
- [HD] MCP connector: "For large tool sets (dozens of tools across several servers), consider enabling `defer_loading` with the Tool search tool"; se recomienda denylist de tools destructivos o "a human confirmation step before state changes".
- [HD] Claude Code (https://code.claude.com/docs/en/mcp): tool search activado por defecto en Sonnet 4.5/Haiku 4.5/Opus 4.5+; `ENABLE_TOOL_SEARCH=auto` difiere tools cuando sus definiciones superan el 10% del contexto (`auto:N` personalizable); descripciones de tool e instrucciones de servidor truncadas a 2KB; resultados MCP >25K tokens (`MAX_MCP_OUTPUT_TOKENS`, aviso a 10K) se guardan a fichero. "The practical limit is your context window budget."
- [INF] Con 200K de contexto, 55K de definiciones sin deferir serían ~28% del presupuesto de Haiku (vs 5.5% en un modelo 1M), y el umbral de 30-50 tools se alcanza con 2-3 servidores MCP (Gmail+Calendar+Drive). Para un secretario en Haiku: allowlist de tools, tool search/defer_loading, tools consolidados, y contexto de tool results recortado.

## Resumen operativo [INF sobre HD]

Haiku 4.5 es válido como clasificador/triage, redactor de borradores y ejecutor de 1-3 tool calls verificables por turno, con `strict: true`, `input_examples`, thinking manual (≥1.024 tokens) para decisiones ambiguas y confirmación humana antes de enviar. No es la elección documentada para loops agénticos largos, planificación multi-paso autónoma ni conversaciones que excedan 200K; ahí Anthropic apunta a Sonnet 5 como worker/driver y a Opus 5 por defecto.
