# Claude Haiku 4.5 as a personal assistant/secretary with MCP: documented facts and inferences

Research date: 2026-09-16. **There is no Haiku newer than 4.5.** The official current-models table lists Fable 5.1, Opus 5, Sonnet 5 and Haiku 4.5; Haiku remains on the 4.5 generation, with retirement "no earlier than Oct 15, 2026" (https://platform.claude.com/docs/en/about-claude/models/overview). Searches for "Haiku 5" return only rumors that Anthropic has not confirmed.

Convention: **[DF]** = fact documented in an official source; **[INF]** = inference drawn from those facts.

---

## 1. Spec sheet and supported features (API)

Sources: https://platform.claude.com/docs/en/models/haiku-4-5/overview and https://platform.claude.com/docs/en/about-claude/models/overview

- [DF] ID `claude-haiku-4-5-20251001` (alias `claude-haiku-4-5`). Released Oct 15, 2025. Official description: "The fastest model with near-frontier intelligence". Comparative latency: "Fastest".
- [DF] Context window **200K** (vs 1M on Sonnet 5/Opus 5/Fable 5.1). Max output **64K** (vs 128K). No 300K output support in Batch (4.6+ models only).
- [DF] Price **$1 / $5 per MTok** (input/output). Cache: 5m write $1.25, 1h write $2, read $0.10. Batch 50% discount.
- [DF] Reliable knowledge cutoff **Feb 2025**, data through Jul 2025 (Sonnet 5: Jan 2026; Opus 5: May 2026).
- [DF] **Thinking: manual "Extended" only** (`thinking: {type:"enabled", budget_tokens:N}`); `type:"adaptive"` returns 400. `budget_tokens` minimum 1,024 and lower than `max_tokens`. **Effort: "Not supported"** (https://platform.claude.com/docs/en/build-with-claude/thinking-troubleshooting, https://platform.claude.com/docs/en/build-with-claude/extended-thinking).
- [DF] **Does not support interleaved thinking** (thinking between tool calls): "Claude Haiku 4.5 does not support interleaved thinking. On the Claude API, the beta header is accepted but ignored." In addition, with manual thinking `tool_choice: any/tool` is not supported (only `auto`/`none`) (https://platform.claude.com/docs/en/agents-and-tools/tool-use/define-tools). Haiku 4.5 discards thinking blocks from previous turns.
- [DF] Vision, tool use, prompt caching (minimum cacheable **4,096 tokens**, higher than other models), structured outputs and strict tool use (supported, no beta header), **tool search / `defer_loading`**: supported (`tool_search_tool_regex_20251119`, `tool_search_tool_bm25_20251119`) (https://platform.claude.com/docs/en/build-with-claude/prompt-caching, https://platform.claude.com/docs/en/build-with-claude/structured-outputs, https://platform.claude.com/docs/en/agents-and-tools/tool-use/tool-search-tool).
- [DF] **Server-side compaction: NOT supported** (https://platform.claude.com/docs/en/build-with-claude/compaction). Neither fast mode, task budgets nor mid-conversation system messages.
- [DF] MCP connector (beta `mcp-client-2025-11-20`): the docs list no per-model restrictions; tool calls only (no resources/prompts), remote HTTP/SSE servers only, not ZDR-eligible (https://platform.claude.com/docs/en/agents-and-tools/mcp-connector).
- [DF] Migration: only `temperature` OR `top_p` (both → 400); handle `stop_reason: refusal`; "Claude 4 models have a more concise, direct communication style" (https://platform.claude.com/docs/en/models/haiku-4-5/migration-guide).
- [DF] Context awareness: trained to know how much context it has left and to "wrap up" as it approaches the limit; useful for limiting "agentic laziness" (system card §1.1.3 https://www.anthropic.com/claude-haiku-4-5-system-card; https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices).
- [INF] For a secretary handling long email/chat threads, the combination of 200K + no compaction + a 4K-token cache minimum forces context management on the client side (own summaries, `context_management` clear_tool_uses, or session rotation).

## 2. Benchmarks and official positioning

- [DF] Announcement (https://www.anthropic.com/news/claude-haiku-4-5): SWE-bench Verified **73.3%**; Terminal-Bench 40.21% (41.75% with 32K thinking); OSWorld 50.7%; "similar levels of coding performance" to Sonnet 4 at 1/3 the cost and >2× the speed; "90% of Sonnet 4.5's performance" on Augment's eval. Recommended pattern, verbatim: "Sonnet 4.5 can break down a complex problem into multi-step plans, then orchestrate a team of multiple Haiku 4.5s to complete subtasks in parallel."
- [DF] System card: "It is not a frontier model, but its high levels of intelligence and speed make it appropriate for a wide variety of 'agentic' uses, including where multiple instances of the model complete tasks in parallel." SWE-bench Verified hard subset: 36.6%. ASL-2.
- [DF] Cost/intelligence guide (https://platform.claude.com/docs/en/about-claude/models/optimizing-for-cost-and-intelligence): "Claude Haiku 4.5 answered GPQA Diamond questions at about a tenth of Opus 5's cost per question, with 63% accuracy compared with 92% for Opus, and fell much further behind on long coding tasks. **It fits high-volume work with checkable outputs, not long agentic loops.**" The measured orchestrator/worker patterns use Sonnet 5 as the worker, not Haiku.
- [DF] Choosing a model (https://platform.claude.com/docs/en/about-claude/models/choosing-a-model): Haiku for "Real-time applications, high-volume intelligent processing, cost-sensitive deployments needing strong reasoning, sub-agent tasks"; an "efficiency-first" approach: start with Haiku, evaluate, move up only if there are gaps. "Most workloads start with Claude Opus 5."
- [DF] Building effective agents (https://www.anthropic.com/engineering/building-effective-agents): routing "easy/common" questions to Haiku and "hard/unusual" ones to Sonnet; agents carry "higher costs, and the potential for compounding errors".
- [INF] Anthropic never recommends Haiku as the *driver* of a long agentic loop; it positions it as a worker/classifier/fast responder. A secretary that only triages, drafts and calls 1-3 tools per turn fits "checkable outputs"; one that plans and chains many autonomous actions does not.

## 3. Documented weaknesses relevant to tool use

- [DF] Missing parameters: "Claude Opus is much more likely to recognize that a parameter is missing and ask for it. Claude Sonnet might ask... But it might also infer a reasonable value... This behavior is not guaranteed, especially for more ambiguous prompts and **for less capable models**." (https://platform.claude.com/docs/en/agents-and-tools/tool-use/overview). [INF] A direct risk for sending email/messages: Haiku may invent a recipient, subject or date instead of asking → use `strict: true`, enums, `required` fields and human confirmation before tools with irreversible effects.
- [DF] System card §4.3: intermediate training checkpoints showed "excessive tool calling, overengineering, and hallucinations"; §1.1.3 mentions "agentic laziness" as a problem mitigated by context awareness. [INF] The docs do not quantify loops in the final model; it is worth setting an iteration limit and deduplicating tool calls on the client side.
- [DF] Prompt injection (system card §3.2, tables 3.2.2.A-C): prevention without safeguards in MCP **92.5%** (Sonnet 4.5: 92.0%), tool use **93.4%** (Sonnet 4.5: 96.0%), computer use 72.2% without / 92.4% with a classifier. The MCP eval simulated "email, Slack, and document collaboration servers" with adversarial instructions in messages/documents. [INF] A secretary that reads incoming email sits exactly on that vector; ~7% successful attacks without safeguards is high if the model can send email, so write tools must require confirmation.
- [DF] Evaluation awareness: 9% of transcripts with verbalized evaluation (system card §4.1.1); less emotive due to reduced sycophancy (§4.6).
- [DF] Tool best practices (https://platform.claude.com/docs/en/agents-and-tools/tool-use/define-tools): descriptions "extremely detailed... at least 3–4 sentences"; consolidate operations into fewer tools with an `action` parameter; namespacing per service; tool responses carrying only high-signal information; `input_examples` improved "accuracy from 72% to 90% on complex parameter handling" (https://www.anthropic.com/engineering/advanced-tool-use). Effective context engineering: "If a human engineer can't definitively say which tool should be used in a given situation, an AI agent can't be expected to do better"; use a "minimal viable set of tools" (https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents).
- [DF] Steering: with `tool_choice: auto` Claude decides per turn; phrases such as "Use the tools to investigate before responding" or "Use your judgment about whether to call a tool" tune the tendency. The tool-use system prompt adds 496 tokens on Haiku 4.5.
- [INF] No official page literally says "instruction drift in long context" for Haiku; the closest is the general "context rot" principle ("the model's ability to accurately recall information from that context decreases" as context grows).

## 4. Claude Code and Haiku

- [DF] `haiku` alias: "Uses the fast and efficient Haiku model for simple tasks". `ANTHROPIC_DEFAULT_HAIKU_MODEL`: "The model to use for `haiku`, or background functionality". Default session model: Opus 5 or Sonnet 5 depending on the plan; Haiku is never the primary default. "Haiku models are always available and can't be disabled" (guaranteed fallback). A Haiku session is upgraded to Sonnet in plan mode unless Sonnet is excluded (https://code.claude.com/docs/en/model-config).
- [DF] Costs: "For simple subagent tasks, specify `model: haiku`"; for agent teams "Use Sonnet for teammates" (https://code.claude.com/docs/en/costs). Subagents: `model: haiku|sonnet|opus|inherit`, `CLAUDE_CODE_SUBAGENT_MODEL` + `CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1`; official Haiku examples: exploration/reading with `tools: Read, Grep, Glob` (https://code.claude.com/docs/en/sub-agents).
- [INF] There is no official sentence saying "Haiku is not recommended as the main model", but the whole design (defaults, the "simple tasks" alias, automatic upgrade in plan mode) treats it as a lightweight-task/subagent model.

## 5. MCP, tool count and context bloat

- [DF] Tool search tool (https://platform.claude.com/docs/en/agents-and-tools/tool-use/tool-search-tool): a typical multi-server setup (GitHub, Slack, Sentry, Grafana, Splunk) consumes "~55k tokens in definitions"; "Claude's ability to pick the right tool degrades once you exceed 30–50 available tools"; use tool search with ≥10 tools or >10K tokens of definitions; keep 3-5 frequently used tools undeferred. Advanced tool use: "Opus 4 improved from 49% to 74%, and Opus 4.5 improved from 79.5% to 88.1%" on MCP evals with tool search; cases of "tool definitions consume 134K tokens" have been observed (https://www.anthropic.com/engineering/advanced-tool-use). There are no Haiku-specific figures.
- [DF] MCP connector: "For large tool sets (dozens of tools across several servers), consider enabling `defer_loading` with the Tool search tool"; a denylist of destructive tools or "a human confirmation step before state changes" is recommended.
- [DF] Claude Code (https://code.claude.com/docs/en/mcp): tool search enabled by default on Sonnet 4.5/Haiku 4.5/Opus 4.5+; `ENABLE_TOOL_SEARCH=auto` defers tools when their definitions exceed 10% of the context (`auto:N` customizable); tool descriptions and server instructions truncated to 2KB; MCP results >25K tokens (`MAX_MCP_OUTPUT_TOKENS`, warning at 10K) are written to a file. "The practical limit is your context window budget."
- [INF] With a 200K context, 55K of undeferred definitions would be ~28% of Haiku's budget (vs 5.5% on a 1M model), and the 30-50 tool threshold is reached with 2-3 MCP servers (Gmail+Calendar+Drive). For a secretary on Haiku: tool allowlist, tool search/defer_loading, consolidated tools, and trimmed tool-result context.

## Operational summary [INF over DF]

Haiku 4.5 is viable as a classifier/triage, draft writer and executor of 1-3 verifiable tool calls per turn, with `strict: true`, `input_examples`, manual thinking (≥1,024 tokens) for ambiguous decisions and human confirmation before sending. It is not the documented choice for long agentic loops, autonomous multi-step planning or conversations exceeding 200K; there Anthropic points to Sonnet 5 as worker/driver and to Opus 5 by default.
